## 一、检测平台标红报告的解析（颜色映射）

平台返回 Word 标红版报告，文字按疑似度着色，**按 run 颜色定位段落**：

| 颜色 | RGB | 疑似度 | 处理优先级 |
|------|-----|--------|-----------|
| 红 | F12828 | ≥70% 高度疑似 | 必改 |
| 橙 | F39800 | 60~70% 中度疑似 | 优先改 |
| 紫 | 9D91E9 | 50~60% 轻度疑似 | 轻量微调 |
| 黑 | 000000 | <50% 正常 | 不动 |
| 灰 | B0B0B0 | 过短/标题/英文 不检测 | 不动 |

解析要点：
- 按段落主颜色归类：统计段内各 run 颜色字符数加权，主色占比 ≥50% 才归类，混合色跳过；
- 过短段（<20 字）跳过（灰色不检测逻辑）；
- 用 `probe_residue.py` 提取标红段原文做改写目标与残留探针基准。

## 二、核心改写手法（实测有效，按优先级）

### 1. 正文"去参数化"（最大杀招）
**原理**：检测器对"函数名 + 参数值 + 逻辑链完整"的算法段天然高敏感——内容越"完整顺滑"越像 AI。

**做法**：正文只讲思路与目的，**函数名保留、参数数值全部下沉附录参数表**（附录 B-I 承载），正文去掉 `delta 取 0.001`、`learningRate 0.01`、`maxIterations（默认 100 次）` 这类罗列。

示例：
- 前：`optimizeIK 用梯度下降求解。每轮迭代以数值微分估算三个关节角对目标位置的偏导，delta 取 0.001，再按 learningRate 0.01 反向更新角度；误差压到 0.001 以下…`
- 后：`optimizeIK 用梯度下降求解，每轮靠数值微分估算关节角对目标位置的偏导，按学习率反向更新；误差压到阈值以下或迭代到上限就停，返回误差最小的解。`

**注意**：函数名（solveIK/executeCommand）保留以维持功能↔源码对应，只去掉参数值。

### 2. 加解释破排比（案例步骤专用）
**原理**：案例操作步骤"① 进入 X 页，点 Y，设 Z，点应用"式连续短句排比是标红重灾区。

**做法**：每步补一句"为什么/看什么"，打破"先进…接着…再…最后…"模板节奏。

示例：
- 前：`先进入「步态模式管理与调度」，点「波浪步态」，占空比设为 0.7，再点「应用参数」。`
- 后：`先到「步态模式管理与调度」页面，选「波浪步态」，占空比拉到 0.7——沙地场景要的就是均匀支撑，然后点「应用参数」。`

### 3. 检测书面化段，打散句式（反弹教训！）
**核心教训**：**降 AIGC 不能走"书面化"路线**。上一轮把紫段轻改成书面化表达（"采用 Electron 技术栈""经 isTransitioning 过渡状态""依据 TerrainInfo 类型推荐"），结果 15 红 → 32 红 **反弹**。书面化 = AI 特征。

**做法**：检测到书面化套话（"采用…技术栈""经…避免""依据…推荐""即停止并返回"）一律打散成口语化+具体化：
- 书面化：`底层采用 Electron、Vue 3、TypeScript 技术栈`
- 口语化：`界面用 Electron、Vue 3、TypeScript 搭的`

书面化模式清单（check_aigc.py --struct 内置扫描）：
```
采用…技术栈 / 经…过渡 / 依据…类型 / 即停止并返回 / 负责…负责…
即可 / 均需 / 均应 / 将…设为 / 设置为…即可 / 整体上 / 由此可见
```

### 4. 亮点短段合并（2 章功能特点）
**原理**："步态这块，三角、波浪、四足三种模式出厂就带着。地形感知给个结论也好…"式口语化短句仍可能被标红——短句密集本身就是特征。

**做法**：亮点内容并入功能特性表（表格不参与 AIGC 检测），正文压成 1 句过渡或与相邻段合并。

### 5. 编号列举改自然段（8 章技术支持）
**做法**：`① 算法定制… ② 接口对接… ③ 培训服务…` 编号列举改自然段叙述，去掉"都安排得了/都能接上"式收尾。

## 三、改写执行规范

1. **改写映射构建**：{检测报告原文: 改写文本} 字典，old 必须用 **python-docx 提取的实际文本**（不要抄检测报告贴文，两者有空格/符号差异）；
2. **整段匹配优先**：先试整段精确匹配（命中率高，实测 42/42）；未命中再降级子串匹配；
3. **残留探针**：改写后重跑 `probe_residue.py`，目标 = 0 全文残留；
4. **探针坑**：首 20 + 尾 20 双端匹配对"改写后首尾未变"的段落会**误报**（实测 3 处），必须用**整段全文匹配**确认；
5. **技术内容零改动**：函数名、源码路径、参数值、公式全部保留，只动叙述表达；
6. **结构完整性**：改写后段落数、表格数、图题数=图位数、8 章标题树不变。

## 五、结构级迭代实战（产线故障推理与决策软件说明书 V1→V4，平台实测驱动）

> 同一平台连续四轮标红报告驱动，验证"只改词句过不了平台，平台认深层结构"。

### 迭代数据（平台标红段数）
| 版本 | 手段 | 红/橙/紫 | 合计 |
|---|---|---|---|
| V1 | 高频词瘦身+长句拆分 | 24/3/6 | 33 |
| V2 | 33 段整段改写（按首份报告） | 16/8/6 | 30（交集 0：改写有效但平台认结构） |
| V3 | 功能列表合并自然段（删 12 段） | 13/0/2 | 15（橙清零） |
| V4 | 2.1/2.4/8.1 **表格化** + 12 段不规则化 | 待复测 | — |

### 核心结论（MUST）
1. **平台检测对象是"结构"而非"用词"**：改写后 V1 33 段与 V2 30 段交集为 0——原文本全换掉仍标红，因为保留了相同深层特征（独立功能短句、平行排比、完整顺滑技术段）。
2. **功能列表段（①②③ 或独立短句）→ 终极手段是表格化**：表格不参与 AIGC 检测，正文留过渡句（"软件的主要用途汇总如下表。"），实测有效；合并自然段（V3）只能降级不能清零。
3. **多列平行排比（环节+动词/X 用…Y 用…/查询类负责…）→ 变换句式**："这一步是感知/负责理解/在推理给出结论"式打破平行，加操作性限定（"数据齐了再返回"）。
4. **字段枚举（"字段包括 A、B、C…"）→ 关系化表述**："设备与指标说明…数值与阈值给出…级别区分…状态从…到…"。
5. **技术流程段（术语密集）**：改写空间有限，平台天然敏感——做最大程度调整后**接受部分红/橙**（软著审查对技术段容忍度高）。
6. **残留探针坑**：改写映射 value 若与 key 相同（技术段没实质改），probe_residue 会报残留——技术段也要至少变序/换衔接词。
7. **合并段副作用**：合并段用"；"+数量词（六方面/几个方面）会引入新的分号并列/数量词命中——检测器启发式命中≠平台标红，需人工复核。
8. **检测器增强闭环**：每轮标红报告 → 分析漏检模式 → check_aigc.py 补模式（V1→11 类启发式，V2→推进词链/功能短句列表）→ 命中率 18%→100%、黑段误报 6%。

## 六、改写自引特征反弹（灵枢智造说明书实测，2026-09）

> 无外部标红报告、纯内置检测驱动的一轮半整段改写（155 段正文改 169 段次）实测：**改写本身会引入新的检测命中**，一轮改写后必须做二轮自检精修。

### 反弹数据（一轮改写前后 --struct 对比）
| 指标 | 改写前 | 一轮后 | 二轮后 |
|---|---|---|---|
| AI 高频词合计 | 61 | 21 | **8**（剩余全在保留项） |
| 分号并列句 | 8 | **16**（自引反弹） | 1（算法流程合理保留） |
| 书面化连接 | 1 | 3（自引"由此/即可/最后"） | 0 |
| 高频词种类 | 14 | 8 | 4 |

### 二轮精修清单（MUST）
1. **拆自引分号**：改写文本爱用"；"推进（破顿号列举时顺手写出），≥2 个分号的段全部改句号成短句；
2. **清自引连接词**："由此/即可/最后/因此/同时"改写时极易顺手写出，二轮逐个清除；
3. **警惕"有没有…有没有"双没有模式**、"两种形式/N 档"数量词复现——破旧模式时别写出新模式；
4. **变异系数代替标准差绝对值**：拆长句后句长标准差数值下降（39→29）是正常现象，看均值/标准差≈0.69 仍处人类区间 0.4~0.7，不误判为劣化；
5. **保留项优先级高于降率**：OMML 公式段（文本双空格占位）、含 \n 的流程段（整段替换丢换行，python-docx 不自动转 `<w:br/>`）、按钮名前导空格（「 AI 交期…」）、emoji（🚚🔔⟳）、联系信息段（"技术支持"字样）一律不动，剩余命中如实交代。

## 七、标红报告驱动三轮实录（灵枢智造 V2→V3，免费检测平台 Word 标红版，2026-09）

> V1（词汇级改写 139 段）+ V2（结构级二轮 28 段）后平台复测仍 红10/橙7/紫13 共 30 段；三轮按颜色定位精修后探针 0 残留。

### 关键发现（MUST）
1. **报告 idx 与正文 idx 不齐**：标红报告插入图例段且中间多出段落（如 62↔61 差 1、297↔291 差 6），**定位一律用文本前缀匹配，禁用 idx 对位**；探针用整段全文匹配兜底。
2. **标红段画像 = 操作流水 + 枚举 + 已改写段**：30 段中标红最多的是"步骤N：切到「X」标签页，按「Y」按钮"式平行流水（无论怎么换词）、"表格展示 A、B、C…N 列"字段/颜色枚举，以及 V2 刚改写过的段（口语化不救结构）。
3. **三轮手法对应**：
   - 平行流水 → 信息顺序重排 + 插入语 + 长短错落（"录完先别急着保存，点一下…"）；
   - 字段枚举 → 关系化（"表格列出的都是风险订单…重点看风险原因字段，延期因素写得很具体——是排产延误，是物料缺货，还是产能不足"）；
   - 技术段 → 换叙述主语与组织方式（"训练集这样组：…"→"训练数据的组织方式：一行一个质检缺陷批次，特征取…标签取…"）；
   - 反问式口语（"上传统 ERP?"）→ 平台同样标橙，改回陈述句。
4. **三轮自引反弹又来一轮**：重构技术段时"最后/其中之一/因此/采用/用于"会再次写出来（高频词 8→16），微调一轮后回到 8（↓87%）——每轮改写后必须用内置检测复扫自引词，成本极低。
5. **紫段（50-60%）轻调即可**：换衔接词、信息顺序微调，不必重写；红段（≥70%）需整段重排。
