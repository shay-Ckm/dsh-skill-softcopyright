# AIGC 审查与降率改写

## Overview

对中文技术文档（说明书 docx、论文等）做 AIGC 生成痕迹审查并降率改写。核心手段：**AI 高频词检测、AI 句式结构检测、书面化表达检测、参数罗列检测、标红段残留探针闭环**。内置静态检测能力，不依赖外部检测平台；若用户已有平台标红报告，可解析其颜色定位段落做实测驱动精修。

## 在交付链路中的位置（软著交付流水线）

```
python-software-delivery Phase 5.1  使用说明书 docx（含「图 N」图位）
        ↓
manual-ui-screenshots                图集截图 + 回填说明书（插图版 docx）
        ↓
【本技能】Phase 5.4                  降 AIGC 率改写 ← 改写对象通常是插图版说明书
        ↓
software-copyright-aigc-appeal       AIGC 检出补正：哈希清单 + 研发日志（生成后也要跑本技能复扫）
```

- **上游产物形态会影响改写执行**：如果上游是 manual-ui-screenshots 回填过的**插图版 docx**，文本段落索引与"仅图位版"不同——改写前先重新导出当前段落清单（`python-docx` 逐段 `p.text`），别沿用旧索引映射表。
- **下游一致性**：改写完成后，除本技能复验外，还要复跑上游的插图版校验（`manual-ui-screenshots/scripts/check_manual_with_figs.py`），确认「图题数 == 图片数」未被破坏。
- **证明文档（software-copyright-aigc-appeal 的产物）也要过一遍本技能**：哈希清单表格 AI 味低，但叙述段仍会命中"本系统/找到实现"等模板词，实测需微调；研发日志的"实现 xxx"模板句式是重灾区（详见该技能第 7 步）。

## Workflow（五步闭环）

```
1. 检测    → scripts/check_aigc.py（词汇级 + --struct 结构/书面化/参数罗列）
2. 定位    → --list 列改写目标段；或解析外部标红报告（红/橙/紫）
3. 改写    → 构建 {原文: 改写} 映射，整段匹配替换
4. 探针    → scripts/probe_residue.py 确认标红段 0 残留
5. 复验    → check_aigc.py 降幅 + 结构完整 + 格式约束
```

## Step 1：检测（内置，不依赖外部平台）

```bash
python scripts/check_aigc.py <docx>            # AI 高频词 / 模板句式 / 句长节奏
python scripts/check_aigc.py <docx> --struct   # 结构性问题 + 书面化套话 + 参数罗列密集段
python scripts/check_aigc.py <docx> --list     # 列出含 AI 痕迹词的正文段落（改写目标）
python scripts/check_aigc.py <docx> --old <旧版>  # 与旧版对比降幅
```

检测指标（与改写手法一一对应）：
1. **AI 高频词**：本软件/同时/此外/通过/实现/采用/进行/提供/支持/用于/旨在/值得注意的是/首先其次最后 等；
2. **模板句式**："该功能由…实现""为用户提供""点击「"等整句框架；
3. **句长节奏**：均值/标准差（突发性，AI <0.3，人类 0.4~0.7）/最长句/超60字句/列举式长句（分号≥3）；
4. **结构性问题**（--struct）："不是A而是B"三毒、二元对比、否定列举、宣告式、虚假能动性、被动语态、极端词、副词过度、**参数罗列密集段**；
5. **排比句检测**（--struct，对应"加解释破排比"改写手法）：排比推进链"先…接着…再…最后"、编号三段式"①②③"、排比指代重复"该方案…该方案…"、段内同类动词重复（"A 包含…；B 包含…"式排比枚举，同词 ≥2 次）；
6. **书面化语句检测**（--struct，对应"打散书面化句式"改写手法）：书面化套话（"对…进行""进行了""予以"）、书面化连接（"从而/进而/以便/由此"）、书面化过程（"在…过程中"）、书面化指代（"该方案能够…"）、书面化收尾（"整体来看/总体而言"）；
7. **平台标红启发式检测**（--struct，基于第三方标红报告实测 33 段反馈补充）：编号标签段（"① 功能名：描述"式）、连续编号列举组（跨段 ≥3 条）、括号注释排比（"感知（…）、理解（…）"≥3 组）、顿号长列举（≥5 项）、数量词引出枚举（"三种/两条/分三类"）、多列动作排比（"X 做…，Y 做…，Z 做…"动作链 ≥4）、分号并列句（分号 ≥2）、高完整度顺滑段（技术引用+顺滑词+介词综合得分 ≥6）、技术归因链（"由 X 管理/供 Y 定位"）、顺滑衔接句（"这样…到…/随时能查"）、引言呼应模板（"本文档与…相互印证"）。
   实测效果：对平台标红 33 段命中率 18% → **100%**，对平台判定正常段误报率仅 6%。

## Step 2：定位目标段落

- **无外部报告**：用 `--list` 输出，跳过标题/图题/步骤/表格（collect_texts 已内置跳过）；
  与 `--struct` 联用时，额外列出**结构性问题命中段落**（含排比/书面化/参数罗列，标注命中片段），
  使"审查定位"与"改写手法"（破排比/打散书面化/去参数化）一一对应；
- **有外部标红报告**（用户上传平台 Word 标红版）：按颜色定位段落——
  | 颜色 | RGB | 疑似度 | 处理 |
  |---|---|---|---|
  | 红 | F12828 | ≥70% | 必改 |
  | 橙 | F39800 | 60~70% | 优先改 |
  | 紫 | 9D91E9 | 50~60% | 轻量微调 |
  | 黑 | 000000 | 正常 | 不动 |
  | 灰 | B0B0B0 | 不检测 | 不动 |
  按段落主颜色归类（run 颜色字符加权，主色占比 ≥50%），导出标红段完整原文作改写目标。

## Step 3：改写（手法 MUST）

改写手法按优先级，详见 `references/rewrite-techniques.md`（实战沉淀）与 `references/aigc-reduction.md`（基础方案）：

1. **正文"去参数化"**（算法段最大杀招）：正文只讲思路，函数名保留、参数数值下沉附录参数表；去掉 `delta 取 0.001` 式罗列；
2. **加解释破排比**（案例步骤）：每步补一句"为什么/看什么"，打破"先进…接着…再…最后…"模板；
3. **书面化段打散句式**（反弹教训）：书面化=AI 特征！"采用…技术栈/经…避免/依据…推荐/即停止并返回"一律打散成口语化+具体化；
4. **亮点短段合并**：功能特点并入表格（表格不参与检测），正文压成过渡句；
5. **编号列举改自然段**：①~④ 枚举改连贯叙述；
6. **语义重构而非换词**：整句重组、换主语、变句式（陈述/祈使/条件）。

**保留项（不得动）**：源码函数名与文件路径、术语定义、公式、技术数值、图位结构、功能↔源码对应表。

**改写执行规范**：
- old 必须用 **python-docx 提取的实际文本**（勿抄检测报告贴文，有空格/符号差异）；
- 整段精确匹配优先（命中率高），未命中降级子串匹配；
- 改写文本不要用"→"箭头（破坏格式约束），用顿号或"之后"。
- **词级兜底替换必须做误伤体检（实测教训，2026-09-27）**：全局 `replace("提供","给出")` / `replace("支持","兼容")` 式词对替换会误伤固定搭配——实测"往往**同时**存在"变成"往往**并且**存在"、"**技术**支持"变成"技术兼容"。规则：
  - 兜底词对只保留**语义等价且不参与固定搭配**的（如"此外/同时"类连接词、纯冗余副词），技术固定搭配（提供支持·技术支持·同时存在·对应关系）**一律走整段改写，不进兜底表**；
  - 替换后必须跑**误伤扫描**：对全部替换词逐个 `if k in p.text` 打印命中上下文，人工过一遍，残留必须 0 再交付。
- **结构性问题命中 ≠ 必须改写**：技术性合理表达（参数被动语态、术语枚举、"系统提供/支持"这类职责描述）保留，先判断再动手（详见 Step 5 第 2 条）。

## Step 4：残留探针（闭环自检）

```bash
python scripts/probe_residue.py <标红报告.docx> <改写后docx.docx> [--colors 红,橙,紫]
```

- 提取标红报告红/橙/紫段原文，在改写后 docx 中做**整段全文匹配**；
- 目标：**0 残留**；
- 坑：首20+尾20双端匹配对"改写后首尾未变"的段会误报，必须用整段全文匹配确认。

## Step 5：复验（交付前 MUST）

1. `check_aigc.py --old`：AI 高频词降幅（目标 ≥50%）、句长标准差提升；
2. `--struct` 复扫：结构性问题仅剩技术性合理表达；
3. **结构完整性**（按上游产物形态选判定口径）：
   - 上游是**仅图位版**：段落数、表格数、**图题数 = 图位数**、章节标题树不变；
   - 上游是**插图版**：改跑 `manual-ui-screenshots/scripts/check_manual_with_figs.py`，判定 **图题数 == 图片数**、残留占位段 0、图号连续；
4. **格式约束**：箭头 0 / Markdown** 0 / 非黑颜色 0 / 斜体 0（若技能 python-software-delivery 存在，用其 check_manual_docx.py）；
5. 交付命名递增：`_降AIGC版.docx` → `_V2` → `_V3`…（多轮迭代）。
6. **改写量参考（实测 2026-09-27，说明书 138 段 / 1.5 万字）**：整段改写 117 段 + 编号列举合并 5 组 + 兜底替换 15 处 → AI 高频词 139 → 29（**↓79%**）、模板句式 1 → 0、结构性问题 104 → 62（编号列举 12→0、技术归因链 8→0），图题/图片/表格数与页数结构完好。**降幅目标 ≥50%，实测可达 70%+ 且不需牺牲技术信息**。

## Resources

### scripts/
- `check_aigc.py` — 内置 AIGC 检测（高频词/模板句式/句长节奏/结构问题/书面化/参数罗列），`--old` 对比降幅；
- `probe_residue.py` — 标红段残留探针（整段全文匹配，0 残留目标）。

### references/
- `aigc-reduction.md` — 降 AIGC 基础方案（三轮递进策略、AI 高频词与模板句式清单、21 类结构性问题清单、改写手法、验证指标）；
- `rewrite-techniques.md` — 实战沉淀（三次检测平台实测：51红→15红→32红反弹教训、去参数化/破排比/书面化打散、颜色解析、探针坑、迭代命名）；
- `detection-report-parsing.md` — 外部检测平台与标红报告解析配合方式（PaperPass/知网/维普，报告贴文与 docx 文本差异）。

### 配套的其他技能脚本（交付链路内复用，勿重复造）
- `python-software-delivery/scripts/check_manual_docx.py` — 仅图位版说明书的格式约束复验（箭头/**/非黑/斜体 0、图题=图位）；
- `python-software-delivery/scripts/manual_stats.py` — 页数/字数统计（`--render` 走 Word COM 取真实渲染页数）；
- `manual-ui-screenshots/scripts/check_manual_with_figs.py` — **插图版**说明书复验（图题数 == 图片数）；
